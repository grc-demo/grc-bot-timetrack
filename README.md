# grc-bot-timetrack

Telegram-бот учёта фактически затраченного рабочего времени по заказам и этапам. Сотрудник фиксирует начало и окончание работы, руководитель получает сводку часов. Эти данные в дальнейшем можно использовать для расчёта фактической себестоимости заказа; сам расчёт себестоимости в первой версии не выполняется.

## Для кого

- **Сотрудник:** отмечает время работы над заказом и этапом без отдельной системы учёта.
- **Руководитель:** смотрит затраты времени по заказам, этапам и сотрудникам в пределах доступных ему данных.

## Сценарии первой версии

1. Сотрудник открывает бота, выбирает доступный заказ и один из этапов: **расчёт, проектирование, производство, контроль, отгрузка**.
2. Нажимает «Начал»; бот сохраняет время начала и показывает активную запись. На одного сотрудника допускается не более одной активной записи одновременно.
3. Нажимает «Закончил», при желании добавляет комментарий; бот сохраняет окончание, длительность и привязку к заказу, этапу и сотруднику. Если активной записи нет, бот не создаёт завершённую запись из ничего.
4. Руководитель запрашивает сводку за период: часы по заказам и этапам, при необходимости — с детализацией по сотрудникам. Доступ к отчётам ограничен ролью руководителя.

Заказы и права доступа к ним должны задаваться администратором вне пользовательского сценария первой версии (например, через начальные данные/административную операцию); конкретный способ наполнения справочника ещё предстоит согласовать. Время хранится как временные метки UTC, длительность считается по паре «начало—конец»; интерфейсные даты и границы отчётного периода требуют согласованной локальной временной зоны. Комментарий необязателен и не влияет на длительность.

## За пределами первой версии

- Расчёт денег, ставок сотрудников, нормативов и фактической себестоимости.
- Интеграции с ERP/CRM, автоматическая синхронизация заказов и экспорт в бухгалтерию.
- Веб-кабинет, мобильное приложение, сложная аналитика и диаграммы.
- Автоматический учёт по геолокации, сменам или событиям оборудования.
- Самостоятельное редактирование закрытых записей и согласование табелей; порядок исправлений определим отдельно.

## Предлагаемая техническая основа

Python 3.12+, aiogram 3 для Telegram, PostgreSQL для данных, SQLAlchemy (async) и Alembic для доступа к БД и миграций, pytest для тестов, Ruff для проверок. Запуск бота в Docker как одного процесса с long polling; в Coolify — приложение из Dockerfile и отдельный ресурс PostgreSQL. При long polling не нужен публичный HTTP-адрес для Telegram, но для одного токена должен работать только один экземпляр polling-процесса. Секреты (`BOT_TOKEN`, `DATABASE_URL`) задаются через окружение Coolify, а не сохраняются в репозитории.

**Статус:** сейчас в репозитории только проектная документация. Бот, Dockerfile, миграции, тесты и команды запуска пока не реализованы. План структуры, будущие команды и ограничения для разработки — в [AGENTS.md](AGENTS.md).
